# Frontend - Умный кредитный кабинет

Клиентский веб-интерфейс на React + TypeScript + Vite для MVP кредитного конвейера малого бизнеса.

## Уже реализовано в demo-режиме

- вход с выбором ролей `client` и `bank_manager`, защищённые маршруты и экран отсутствия доступа;
- дашборд клиента и список его заявок;
- каталог с фильтрами по сумме и сроку;
- пятишаговый мастер: потребность, компания, заявитель, документы, проверка и отправка;
- карточка заявки клиента с историей статусов и результатными действиями;
- банковская очередь, поиск, фильтры, вкладка ручного решения и карточка со скорингом/проверками;
- действия менеджера: одобрение, изменение условий, запрос информации, отказ (в демо без записи в сервер);
- уведомления, empty- и loading-friendly состояния;
- API-слой, готовый к подключению Django REST Framework;
- production Docker-образ с Nginx и SPA fallback.

## Запуск

```bash
npm install
npm run dev
```

Откройте `http://localhost:5173`.

### Режимы API

- `VITE_USE_MOCKS=true` - MSW перехватывает запросы и отдаёт синтетические данные; сервис запускается без backend.
- `VITE_USE_MOCKS=false` - запросы направляются в Django DRF по `VITE_API_URL`.

Для mock-режима worker уже лежит в `public/mockServiceWorker.js`.

## Что подключается к Django на следующем этапе

Сейчас интерфейс использует синтетические данные; авторизация и решения не являются источником истины. После настройки `VITE_API_URL` нужно заменить demo-методы на DRF-эндпоинты и реализовать:

- JWT access/refresh, refresh при `401`, logout при истечении refresh;
- сохранение черновиков, серверную валидацию и `Idempotency-Key` при создании заявки/решении;
- upload/download документов;
- WebSocket статуса/уведомлений через Django Channels и polling fallback;
- TanStack Query для server state, retry, cache invalidation и skeleton loading.

Минимальный REST-контракт:

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/products/` | Список продуктов |
| `GET` | `/applications/current/` | Текущая заявка клиента |
| `POST` | `/applications/` | Создание заявки |

Модель заявки: `id`, `productId`, `amount`, `termMonths`, `purpose`, `status`, `createdAt`. Статусы: `draft`, `submitted`, `review`, `additional_info`, `approved`, `declined`.
