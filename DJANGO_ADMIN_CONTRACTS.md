# Django Admin и данные

Этот документ фиксирует работающий интерфейс администрирования Django и структуру базы данных. Он дополняет [BACKEND_API_ACTUAL.md](BACKEND_API_ACTUAL.md): здесь описан cookie-based интерфейс `/admin/`, а не JWT API.

## Доступ в админку

| Путь | Метод | Кто имеет доступ | Результат |
| --- | --- | --- | --- |
| `/admin/` | `GET` | Django-пользователь с `is_staff=true` | Главная страница админки |
| `/admin/login/` | `GET`, `POST` | Все | Вход по `username` и паролю Django |
| `/admin/core/loanapplication/` | `GET` | Пользователь с правом `view_loanapplication` | Очередь заявок с фильтрами и поиском |
| `/admin/core/uploadeddocument/` | `GET` | Пользователь с правом `view_uploadeddocument` | Реестр документов |
| `/admin/core/uploadeddocument/{id}/preview/` | `GET` | Пользователь с правом просмотра документов | Защищённый бинарный просмотр PDF/JPG/PNG |

Административный просмотр файлов использует Django-сессию и `admin_view`; ссылка на файл не является публичной. При отсутствии записи или файла возвращается `404`.

Для локального демо команда `python manage.py seed_demo` создаёт суперпользователя:

```text
Логин: admin@alfa.local
Пароль: DemoAdmin2026!
```

Не используйте эти учётные данные вне локальной демонстрации.

## Экраны

| Раздел | Возможности |
| --- | --- |
| Пользователи | Поиск, статус staff/active, профиль с ролью, компанией, ИНН и телефоном |
| Заявки | Поиск по номеру/клиенту/компании, фильтр по статусу и продукту, назначение менеджера, комментарий решения, история и документы внутри карточки |
| Документы | Поиск по имени/заявке/клиенту, фильтр статуса, безопасная кнопка «Открыть» |
| Продукты | Изменение параметров продукта и быстрая активация/деактивация |
| Уведомления | Просмотр уведомлений, фильтр прочитанности |

## База данных

СУБД — **PostgreSQL 16**. В Docker Compose используется сервис `db`, данные хранятся в именованном Docker volume `postgres_data`. Django подключается драйвером `django.db.backends.postgresql`.

Параметры подключения обязательны в `.env`:

```env
DB_NAME=...
DB_USER=...
DB_PASSWORD=...
DB_HOST=db
DB_PORT=5432
```

### Таблицы предметной области

| Модель / таблица | Назначение | Связи |
| --- | --- | --- |
| `auth_user` | Учётные записи Django | 1:1 с `core_profile` |
| `core_profile` | Роль, компания, ИНН и телефон | `user` → `auth_user` |
| `core_product` | Кредитные продукты | используется в заявках |
| `core_loanapplication` | Кредитные заявки | `client`, `manager` → `auth_user`; `product` → `core_product` |
| `core_applicationhistory` | История статусов | `application` → `core_loanapplication` |
| `core_uploadeddocument` | Метаданные и путь к файлу | `application` → `core_loanapplication`; `user` → `auth_user` |
| `core_notification` | Уведомления | `user` → `auth_user`; необязательная `application` → `core_loanapplication` |

Файлы документов не хранятся в PostgreSQL: в БД сохраняется путь `file`, а файл находится в `MEDIA_ROOT` (локально `backend/hack2026_site/media/`).

## Правила целостности

- Удаление заявки каскадно удаляет её историю, документы и связанные уведомления.
- Удаление продукта, выбранного в заявке, запрещено (`PROTECT`).
- При удалении менеджера поле `manager` в заявке становится `NULL`.
- Идентификатор заявки генерируется в формате `CR-XXXXXX` при сохранении.
